# API 명세 작성 · HTML 발행

API 문서가 죽는 이유는 두 가지다. **(1) 코드가 바뀌었는데 문서가 안 바뀌거나, (2) 문서가 여러 벌이라
서로 어긋난다.** 이 스킬은 그 둘을 막는 절차다.

원칙: **마크다운이 유일한 원본(single source), HTML 은 그것에서 생성한 산출물.**
사람이 HTML 을 직접 손대는 순간 두 벌이 되고, 다음 생성에서 조용히 사라진다.

---

## ⛔ 필수 입력 — 서버 베이스 URL 없이는 시작하지 않는다

**엔드포인트 주소(베이스 URL)는 선택 인자가 아니다.** 받는 쪽이 `POST /decrypt/approve` 만
보고 할 수 있는 일은 없다. 어디로 쏘는지가 빠진 문서는 문서가 아니라 메모다.

**게이트 — 다음 순서를 그대로 지킨다.**

1. 인자에 베이스 URL 이 있으면 그대로 쓴다 (`https://api.example.com`, `https://api.example.com/v1`).
2. 없으면 **먼저 코드·설정에서 찾아본다** — 기존 `API_SPEC.md` 상단, `application*.yml`/`.properties`,
   `.env`, 배포 매니페스트, README. 찾았으면 **출처와 함께 사용자에게 확인받고** 진행한다.
   ("`application-prod.yml` 에서 `https://api.example.com` 을 찾았습니다. 이 주소로 쓸까요?")
3. 그래도 없으면 **사용자에게 묻고 멈춘다.** 환경이 여러 개면 환경별로 다 받는다
   (운영 / 스테이징 / 개발).
4. **답을 받기 전에는 마크다운도 HTML 도 만들지 않는다.** 임의의 주소를 지어내지 않고,
   `https://<TBD>` 같은 자리표시자로 채워 넘어가지도 않는다 — 그 문서는 그대로 업체에 나간다.

> 예외는 하나뿐이다. **이미 베이스 URL 섹션이 있는 기존 문서를 갱신하는 경우** — 그 값을 그대로
> 쓰고 다시 묻지 않는다. 단, 그 값이 이번 변경으로 달라졌는지는 확인한다.

받은 값은 **문서 상단(개요 바로 아래)에 고정 섹션으로 적는다.** 개별 엔드포인트의 경로는
이 베이스 URL 기준의 상대 경로임을 함께 명시한다.

```markdown
## 베이스 URL

| 환경 | 주소 |
|---|---|
| 운영 | `https://api.example.com/v1` |
| 스테이징 | `https://stg-api.example.com/v1` |

아래 모든 엔드포인트 경로는 이 베이스 URL 에 이어 붙인다. 예: `POST /decrypt/approve`
→ `POST https://api.example.com/v1/decrypt/approve`
```

이 섹션은 마크다운 본문에 들어가므로 HTML 에도 자동으로 함께 실린다 — 템플릿을 손댈 일은 없다.

## 🔒 템플릿은 고정이다 — 다시 설계하지 않는다

HTML 껍데기는 이 스킬 폴더에 **완성된 상태로 동봉돼 있다.**

```
skills/apispec/template/
├── md2html.py    마크다운 → HTML 변환기 (표준 라이브러리만 사용)
└── shell.html    레이아웃 · CSS · JS 껍데기
```

**이 두 파일을 프로젝트로 복사해서 그대로 쓴다.** 디자인을 새로 고민하거나, 더 나아 보이는 구조를
제안하거나, CSS 를 다시 짜지 않는다. 문서마다 생김새가 달라지면 그 순간 "우리 API 문서" 라는 것이
없어진다.

### 바꿔도 되는 것 — 이게 전부다

| 무엇 | 방법 |
|---|---|
| 문서 제목 | 마크다운 최상단 `# 제목` (헤더 브랜드로 올라가고 본문에서는 빠진다) |
| 부제 라벨 | `--subtitle "조직 · 서비스명"` |
| 좌측 배지 문구 | `--mark API` (2~3글자) |
| 상대 링크 보정 | `--rel-prefix ../` (출력이 하위 디렉토리일 때) |
| 본문 내용 | 마크다운 |

### 바꾸면 안 되는 것

색 팔레트(라이트/다크/clay 3종 · 메서드별 색), **레이아웃 구조(엔드포인트 좌 · 본문 · 목차 우)**,
패널 동작(접기 · 폭 조절 · 스크롤 스파이 · 필터), 헤더 구성과 버튼, 키보드 단축키,
`localStorage` 키 이름, 인쇄 스타일, 앵커 슬러그 규칙.

> 정말로 템플릿 자체를 고쳐야 하는 이유가 생기면 **사용자에게 먼저 확인**하고, 프로젝트 사본이
> 아니라 **이 스킬의 `template/` 을 고친 뒤 프로젝트로 다시 복사**한다. 프로젝트에서만 고치면
> 다음 프로젝트가 그 개선을 못 받고, 두 벌로 갈라진다.

### 설치와 사용

```bash
# 1) 최초 1회 — 템플릿을 프로젝트에 복사(생성기를 저장소에 함께 둔다)
mkdir -p etc/spec-html && cp <skill>/template/{md2html.py,shell.html} etc/spec-html/

# 2) 생성 — 마크다운을 고칠 때마다
python3 etc/spec-html/md2html.py API_SPEC.md docs/API_SPEC.html --subtitle "조직 · 서비스명"
```

산출물만 두고 생성기를 빼지 않는다. 생성기가 없으면 다음 사람이 HTML 을 손으로 고치기 시작한다.

## 화면 구성 (세 칸)

| 칸 | 내용 | 만들어지는 방법 |
|---|---|---|
| **좌: 엔드포인트** | 메서드 칩 + 경로. 그룹으로 묶임 | 아래 두 소스를 **병합** |
| **가운데: 본문** | 명세 전문 | 마크다운. 단 `## 목차` 섹션은 우측과 중복이라 **HTML 에서 자동 제거** |
| **우: 목차** | 문서 구조(h2~h4) | 제목에서 자동 |

좌측 목록의 소스는 둘 다 읽는다 — 문서마다 한쪽만 있는 경우가 많다.

1. **메서드가 들어간 제목** — `#### 3.2.6 POST \`/decrypt/approve\` — 결재 승인`,
   `### 대시보드 통계 — \`GET /admin/dashboard/stats\`` (앞·뒤 어디든, h3 이상)
2. **엔드포인트 색인 표** — 제목에 `색인 / 전체 목록 / 엔드포인트 목록` 이 들어간 섹션의 표.
   `메서드`·`경로` 열은 필수, `설명`·`내용` 열은 선택. `| **인증** |` 처럼 한 칸만 채운 행은 그룹 머리글.
   그룹 행이 없으면 경로 첫 마디(`/admin`)로 묶는다.

표에만 있고 상세 절이 없는 엔드포인트도 목록에는 남긴다(링크만 없음) — 목록에서 빠지면 누락으로 읽힌다.
`POST \`/x/request-approve\` · \`/cancel\`` 처럼 한 절이 여러 엔드포인트를 묶어 설명해도 꼬리 경로까지
그 절로 연결한다.

## 템플릿이 이미 보장하는 것 (다시 만들지 말 것)

- **외부 리소스 요청 0건** — CSS·JS 전부 인라인. 폰트는 시스템 폴백. 폐쇄망·오프라인·`file://` 에서 열린다.
- **GitHub 앵커 규칙 구현** — 마크다운의 `#...` 내부 링크가 HTML 에서 그대로 살아 있다.
- **마크다운 처리** — 제목·표(정렬 포함)·코드펜스·인용(콜아웃)·목록(중첩)·수평선·인라인 서식.
  목록 안에 들여쓴 표·코드펜스도 블록으로 잡는다.
- **코드 밖 리터럴 꺾쇠 이스케이프** — `<Base64 인코딩 파일>` 같은 본문 텍스트가 태그로 먹히지 않는다.
  통과시키는 인라인 태그는 화이트리스트(`<br>` · `<b>`)뿐.
- **엔드포인트 제목의 메서드 칩** — `#### 3.2.6 POST \`/path\` — 설명` 형태를 인식해 색 배지를 붙인다.
- **읽기 도구** — 양쪽 패널 각각 접기 · 드래그로 폭 조절 · 현재 위치 추적, 한 입력으로 양쪽 동시 필터,
  코드 복사, 라이트/다크 · 톤 전환(선택 기억), 인쇄 스타일, `/` 로 검색 포커스.
- **빈 패널 방지** — 엔드포인트를 하나도 못 찾으면 좌측 패널과 그 버튼을 아예 내린다.

## 진행 순서

0. **베이스 URL 확보 (게이트 — 통과 못 하면 여기서 멈춘다)** — 위 "필수 입력" 절차대로 인자 →
   코드·설정 → 사용자 질문 순으로 확보한다. 확보 전에는 아래 단계를 시작하지 않는다.
1. **범위 확정** — 인자가 있으면 그 대상, 없으면 `git diff`(스테이징 포함)로 이번 변경분을 대상으로
   한다. 컨트롤러·DTO·에러코드·마이그레이션 변경이 문서에 반영돼야 할 것들이다.
2. **기존 문서 관용구 학습 (반드시 먼저)** — 새 섹션을 쓰기 전에 이 문서가 이미 쓰는 방식을 조사한다.
   섹션 번호 체계, 표의 열 구성(`필드 / 타입 / 필수 / 설명`), 예시 JSON 의 상세도, 권한 표기 방식,
   에러코드 표의 위치. **주변과 다른 형식으로 쓰지 않는다.**
3. **코드에서 사실 확인** — 경로·메서드·필수 여부·기본값·권한을 **컨트롤러와 DTO에서 직접 읽어**
   적는다(아래 "근거 규칙").
4. **마크다운 갱신** — 본문 + 엔드포인트 색인 + 에러코드 표를 함께 고친다. 하나만 고치면 어긋난다.
5. **HTML 재생성** — 동봉된 생성기를 돌린다. **마크다운만 커밋하고 끝내지 않는다.**
6. **검증** — 아래 체크리스트를 실제로 돌린다. "잘 됐을 것"은 검증이 아니다.

## 무엇을 적나 (엔드포인트 1건 기준)

- **경로·메서드·성공 상태코드** — 실제 매핑 애노테이션에서 읽는다.
- **권한** — 메서드 보안 애노테이션 + 서비스의 실제 검증. **진입 가능과 실행 가능은 다르다**
  (진입은 되는데 서비스가 거부하는 경우를 따로 적는다).
- **요청** — 예시 JSON + 필드 표(타입 · 필수 · 설명). 필수 여부는 검증 애노테이션에서 확인한다.
- **응답** — 예시 JSON + 필드 표. **선택 필드와 항상 오는 필드를 구분**한다. 빈 값이 `null` 인지
  빈 배열인지 명시한다 — 클라이언트 분기가 여기서 갈린다.
- **에러** — 이 엔드포인트가 실제로 내는 코드만. 전역 표에 있다고 생략하지 말고 링크한다.
- **함정** — 전체 재설정(부분 갱신이 아님), 1회용 토큰, 멱등성, 크기 상한, 조회 범위가 호출자
  권한에 따라 서버에서 정해지는 경우. **문서에서 이걸 빠뜨리면 반드시 사고가 난다.**

## 근거 규칙 (추정 금지)

- 필드의 **필수 여부**는 검증 애노테이션에서 확인한다. "필수일 것 같다"로 적지 않는다.
- **권한**은 애노테이션 + 서비스 검증 양쪽을 본다. 한쪽만 보면 틀린다.
- **기본값·상한**은 설정 파일이나 상수에서 읽어 값과 함께 출처를 적는다.
- 코드에서 확인할 수 없는 항목(외부 시스템 응답 형태 등)은 **"미확인"으로 표시**하고 넘어간다.
  그럴듯하게 지어내면 문서를 믿을 수 없게 되고, 그때부터 아무도 안 본다.

## 검증 체크리스트 (전부 실제로 확인)

| 항목 | 통과 기준 |
|---|---|
| **베이스 URL** | **문서 상단에 베이스 URL 섹션이 있고, 실제 호출 가능한 주소다. `<TBD>`·`example.com` 자리표시자로 남아 있지 않다(가상 예시가 의도된 대외 문서는 제외)** |
| 플레이스홀더 | 치환되지 않은 `{{...}}` 0건 |
| 내부 앵커 | 문서 내 `#링크` 전부가 실제 heading id 로 해석됨 |
| 좌측 패널 | 엔드포인트 수가 색인 표와 일치하고, 링크가 **의도한 절**로 감(무링크 항목은 상세 절이 없는 것만) |
| 본문 목차 | `## 목차` 섹션이 본문에서 사라지고 우측 패널에만 남음 |
| 외부 리소스 | `src`/`href` 에 원격 주소 0건 |
| 태그 균형 | `table`/`tr`/`pre`/`ul`/`li` 등 열림·닫힘 수 일치 |
| 마크다운 잔재 | 표 구분행·코드펜스가 본문에 그대로 남지 않음 |
| 스크립트 | 임베드된 JS 문법 오류 없음(`node --check`) |
| 내용 일치 | 이번에 고친 항목이 **양쪽 산출물에 모두** 반영됨 |

## 안전 제약

- **베이스 URL 없이 문서를 만들지 않는다.** 지어내거나 자리표시자로 채우고 넘어가지 않는다 —
  물어보고 기다린다.
- **템플릿의 디자인·기능을 임의로 바꾸지 않는다.** 위 "바꿔도 되는 것" 표에 없는 것은 사용자 확인 없이 건드리지 않는다.
- **HTML 산출물을 직접 편집하지 않는다.** 바꿔야 하면 템플릿을 고치고 다시 생성한다.
- **마크다운만 고치고 끝내지 않는다.** 두 산출물은 같은 커밋에 함께 들어간다.
- **문서를 맞추려고 코드를 바꾸지 않는다.** 코드가 틀렸다고 판단되면 문서에 적지 말고 따로 보고한다.
- 대외 배포 문서의 예시에는 **실명·사번·사내 이메일·실제 파일명·업무 내용을 넣지 않는다.** 가상
  데이터를 쓴다. 이미 들어간 것을 발견하면 교체하고, **git 이력과 배포된 사본에는 남는다는 점을
  함께 알린다.**

## 출력

작업 후 두괄식으로 보고한다: 결론 한 줄 + 변경 요약 표(대상 · 무엇을 · 어느 산출물에) +
검증 결과(체크리스트 통과 여부) + 확인하지 못한 항목. 확인 못 한 것을 숨기지 않는다.
